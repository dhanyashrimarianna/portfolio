Projects (tap to open)

Two projects, start to finish: requirements, SQL, models, and dashboards.

Olist: growth & retention PostgreSQLPythonstatsmodelsGit
  • This was a simulated BA engagement using public Olist e-commerce data (99K orders). The problem was low retention, so I wrote a stakeholder map with RACI, a BRD (9 KPIs, 13 requirements), and 12 user stories with acceptance criteria.
  • I built a PostgreSQL star schema with 11 automated data-quality checks. Along the way, I caught that customer_id is unique per order, which would have shown a 0% repeat rate, so I rebuilt the customer logic on customer_unique_id.
  • Only 3.0% of 93K customers ever reordered. Late deliveries averaged 2.27 review stars, compared to 4.29 for on-time ones.
  • I tested whether a late first delivery lowers the return rate (0.92% vs. 1.25%, p = 0.027). Category varied even more (0.80% to 1.75%), so I refined my recommendations.
  • I prioritized four improvement opportunities using RICE and sensitivity analysis, drafted a PRD, and designed an A/B test (about 9,100 customers per group to detect a +0.5 point lift in 90-day repeat rate).
  • See the code on GitHub ↗
PayNext: why payments fail Random ForestPower BIMatplotlib
  • I generated a synthetic dataset of 50,000+ payment transactions to mimic a real payment system.
  • EDA and feature engineering (retry count, gateway latency, payment method, device, and geography) helped me figure out what’s behind failed transactions.
  • My Random Forest model (scikit-learn) predicts transaction success with 85% accuracy, and I used its outputs to simulate smarter routing.
  • I built Power BI and Matplotlib dashboards for success rate, failure reasons, and gateway performance.
